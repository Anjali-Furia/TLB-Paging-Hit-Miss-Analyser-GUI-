## 1. Executive Summary

In virtual memory systems, the **Translation Lookaside Buffer (TLB)** is a critical hardware cache responsible for storing virtual-to-physical address translations. The performance of virtual memory translation heavily dictates overall CPU performance.

The **TLB Paging Hit/Miss Analyser** is an educational, interactive web-based simulator designed to:
1. Provide a transparent, step-by-step trace of how virtual page references interact with a hardware TLB and physical memory.
2. Compare a **Traditional FIFO-based TLB replacement strategy** against an advanced **DEPOT-inspired protection mechanism**.
3. Compute and contrast industry-standard OS performance metrics including **Hit Ratio**, **Miss Ratio**, and **Effective Access Time (EAT)**.
4. Elevate educational comprehension through an aesthetic **Cyber-Neon 3D WebGL** particle visualizer and animated data charts.

## 2. Core Operating System Fundamentals

### 2.1 The Two-Level Memory Access Problem
When virtual memory is active, each memory reference instruction generated by the processor uses a virtual address. Without a TLB:
1. The CPU accesses the Page Table in main memory to translate the Virtual Page Number (VPN) to a Physical Frame Number (PFN).
2. The CPU performs the actual read/write access to the computed physical address.

This doubles the memory access penalty:
$$\text{Access Latency} = 2 \times t_{\text{mem}}$$

### 2.2 Translation Lookaside Buffer (TLB)
The TLB is an on-chip, fast associative memory (content-addressable memory) that caches the most frequently accessed page table entries (PTEs).

```
                      +-------------------+
                      |   Virtual Address |
                      +---------+---------+
                                |
                   [Virtual Page Number (VPN)]
                                |
                                v
                      +-------------------+
                      |  TLB Cache Check  |
                      +----+---------+----+
                           |         |
                  HIT      |         |     MISS
          +----------------+         +----------------+
          |                                           |
          v                                           v
[Get PFN from TLB]                         [Access Main Memory Page Table]
          |                                           |
          |                                   [Load PTE into TLB]
          |                                           |
          +----------------+--------------------------+
                           |
                           v
              [Access Physical Memory]
```

### 2.3 Mathematical Model: Effective Access Time (EAT)
Let:
- $\alpha$: TLB Hit Ratio ($0 \le \alpha \le 1$)
- $t_{\text{TLB}}$: TLB lookup latency (e.g., $10\text{ ns}$)
- $t_{\text{mem}}$: Main memory access latency (e.g., $100\text{ ns}$)

#### Case 1: TLB Hit
The translation is resolved in the TLB cache.
$$\text{Time}_{\text{Hit}} = t_{\text{TLB}} + t_{\text{mem}}$$

#### Case 2: TLB Miss
The lookup in TLB fails. The hardware walks the page table in RAM (1 memory access) and then accesses the actual operand/instruction in RAM (1 memory access).
$$\text{Time}_{\text{Miss}} = t_{\text{TLB}} + t_{\text{mem}} + t_{\text{mem}} = t_{\text{TLB}} + 2 \times t_{\text{mem}}$$

#### Overall Effective Access Time (EAT)
$$\text{EAT} = \alpha \times (t_{\text{TLB}} + t_{\text{mem}}) + (1 - \alpha) \times (t_{\text{TLB}} + 2 \times t_{\text{mem}})$$

Or expanded algebraically:
$$\text{EAT} = t_{\text{TLB}} + (2 - \alpha) \times t_{\text{mem}}$$

## 3. Algorithmic Implementations

### 3.1 Traditional TLB Replacement (FIFO)
In the traditional model:
- Entries are stored in a fixed-size buffer of capacity $N$.
- When a page reference arrives:
  1. If present $\rightarrow$ **HIT**.
  2. If absent $\rightarrow$ **MISS**.
     - If the cache has vacant slots, the page is appended.
     - If the cache is full, the oldest entry at index 0 is evicted (**FIFO** policy), and the new page is pushed to the tail.

#### Pseudocode:
```javascript
function runTraditionalTLB(capacity, sequence):
    tlb = []
    for page in sequence:
        if page in tlb:
            record HIT
        else:
            record MISS
            if length(tlb) >= capacity:
                evicted = tlb.shift() // FIFO eviction
            tlb.push(page)
```

---

### 3.2 DEPOT-Inspired TLB Replacement
Traditional FIFO and LRU algorithms suffer from **dead-entry thrashing** when loop boundaries or cyclic memory access sequences exceed cache capacity. A page evicted from the cache may be requested again immediately, resulting in consecutive misses.

The **DEPOT-Inspired Architecture** in this simulator solves this problem through intelligent partition tracking:
1. **`recentlyEvicted` Tracker**: A set tracking pages that were recently pushed out of the TLB.
2. **Dead-Entry Classification**: If an incoming page is a miss **and** exists in `recentlyEvicted`, it is marked as a **`DEAD-ENTRY MISS`**.
3. **Protected Partition (`protectedSet`)**:
   - When a dead-entry miss occurs, the page has proven its high utility. Upon reloading, it is inserted into the `protectedSet`.
   - When cache eviction occurs, the algorithm searches for a victim page that is **not** in `protectedSet`.
   - If all cached pages are protected, it falls back to standard FIFO order to prevent deadlock.
   - When a page is finally evicted, it is removed from `protectedSet` and moved into `recentlyEvicted`.

#### Pseudocode:
```javascript
function runDEPOT(capacity, sequence):
    tlb = []
    protectedSet = new Set()
    recentlyEvicted = new Set()

    for page in sequence:
        if page in tlb:
            record HIT
        else:
            if page in recentlyEvicted:
                record DEAD_ENTRY_MISS
                isDead = true
            else:
                record NORMAL_MISS
                isDead = false

            if length(tlb) >= capacity:
                // Find first non-protected page
                victimIdx = findIndex(p not in protectedSet)
                if victimIdx == -1: victimIdx = 0

                evictedPage = tlb.remove(victimIdx)
                protectedSet.delete(evictedPage)
                recentlyEvicted.add(evictedPage)

            tlb.push(page)
            if isDead:
                protectedSet.add(page)
```

```text
     +--------------+                      | - Chart Gen  |
                                           +--------------+
```

### 4.1 Graphics & Visualizer (`Three.js`)
- An interactive WebGL canvas renders 700 glowing particle points in 3D coordinate space using `THREE.BufferGeometry` and `THREE.PointsMaterial`.
- A continuous requestAnimationFrame loop updates rotation based on elapsed clock time and mouse cursor offsets ($X, Y$).

### 4.2 Interactive Step-by-Step Stepper
In addition to running full batch simulations, users can step through each memory request using the **Next Step** button:
- Managed via `stepperState = { active, currentIndex, logs }`.
- Rows are progressively added with custom CSS keyframe animations (`row-cascade`).
- Real-time indicator tracks `Step X / Total`.

### 4.3 Input Validation & Defensive Design
- Strict bounds checking on numerical fields:
  - `TLB Size > 0`
  - `Page Size > 0`
  - `TLB Lookup Time >= 0`
  - `Memory Access Time > 0`
- Sequence parser handles comma or space delimited integers and strips invalid characters.
- Error banner triggers with animated shake feedback.

## 5. Comparative Evaluation

| Feature / Metric | Traditional FIFO TLB | DEPOT-Inspired TLB |
|---|---|---|
| **Eviction Policy** | First-In, First-Out | Protected-Set Aware Victim Selection |
| **Dead-Entry Awareness** | None (Blind FIFO) | High (Tracks recently evicted pages) |
| **Thrashing Resilience** | Low under cyclic sequences | High (Protects frequently re-used pages) |
| **Hardware Overhead** | Minimal (Simple counter/queue) | Modest (Requires tracking tag bits/protection flags) |
| **Effective Access Time** | Higher under cache contention | Significantly lower for re-referenced working sets |
